# TestVVE

## Что сделала

* API с 4 эндпоинтами:
	* POST Создание задачи: 201 при успехе + созданная модель, 400 при некорректном Title.
	* GET Получение всех задач: 200 при успехе + список задач.
	* PUT Завершение задачи: 200 при успехе, 404 если задачи нет, 409 если уже завершена или параллельное завершение другим потоком.
	* DELETE Удаление задачи: 204 при успехе, 404 если задачи нет.
* БД:
	* Миграции.
	* Обработка конкурентности через `xmin`.
* RabbitMQ:
	* Тихая обработка исключений с логированием.
	* Graceful Shutdown: `DisposeAsync` с асинхронным закрытием канала и подключения.
* Интеграционный тест.
* Конфигурация подключения к PostgreSQL и RabbitMq в appsettings.Development.

## Как проверяла

* Postman - каждый эндпоинт.
* dotnet test - успешное прохождение интеграционного теста.
* UI RabbitMQ - видна активность при отправке сообщения, сообщение приходит в очередь в нужном формате.

## Что планировала, но не успела

* Ленивая загрузка в RabbitMQ, чтобы избавиться от `.GetAwaiter().GetResult()`. Сейчас при первом запросе будет попытка создания сервиса (синхронно) - если RabbitMQ не запущен, будет задержка, и в запросе PUT 500 ошибка. Планировался отдельный метод с подключением, который выполнил бы подключение при первом запросе в RabbitMQ.
* Retry для RabbitMq: 2-3 попытки, чтобы сообщение отправилось даже при временном сбое.
* Проверка в интеграционном тесте, что RabbitMQ получил сообщение.

## Инструкция запуска

* Поднять PostgreSQL и RabbitMQ.
* В UI RabbitMQ создать queue `task.completed.queue` и привязать её к Exchange `task.events` с routing key `task.completed`.
* Добавить конфигурации подключения к PostgreSQL и RabbitMQ в appsettings.Development.
* Применить миграции: dotnet ef database update.
* Запустить: dotnet run.
* Проверить тест: dotnet test.
